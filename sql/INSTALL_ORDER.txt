# ad4_38 grants the write path to service_role and prints one row per ingest
# table saying whether the service key can write it. It is last on purpose -
# every table that exists by then is covered - and it is safe to re-run alone
# the moment an n8n workflow reports `permission denied ... (42501)`.
#
# ad4_39 publishes v_data_freshness: one row per table the UI depends on, with
# how many rows it holds, how old the newest one is, and whether that counts as
# absent / empty / stale / ok. Every page reads it, so an empty panel can say
# which job stopped filling it instead of just showing nothing.
#
# ad4_40 publishes v_synthesis_findings and v_learning_state: what the archive
# has established, in sentences, each carrying the span, the cities and the
# count behind it - and the four dated artefacts that make up "the desk has
# learned something". The Synthesis page is entirely these two views.
#
# ad4_41 makes a campaign show what it would actually do: the cities its target
# resolves to, what is live inside that scope, what its own strategy would take
# right now, and the first reason it cannot.
#
# ad4_42 answers whether a backtest window has any data in it BEFORE the run,
# rather than after twenty minutes of Actions time.
#
# ad4_43 publishes v_forecast_audit: for each city, the forecast the board is
# showing, which model and lead it came from, every other row available for the
# same day, what has actually been observed, and a verdict naming the most
# likely cause when the number looks wrong. Run it the moment a forecast looks
# off - it distinguishes "the model was wrong" from "the view read the wrong
# row", which need completely different fixes.
#
# ad4_44 adds the indexes four of the busiest tables never had - book_snapshots,
# trades_observed, bands and markets carried nothing but a surrogate primary
# key, so every lookup was a full table scan. That is where
# `canceling statement due to statement timeout (57014)` comes from. Measured
# cold on a 650k-row archive: the whole set of queries the UI makes went from
# 6.0s to 1.9s, and the worst single view from 2.6s to 42ms.
