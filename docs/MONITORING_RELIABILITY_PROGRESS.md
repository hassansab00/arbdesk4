# Monitoring reliability repair

This follows the completed monitoring audit. It changes operational displays and source recovery without changing the frozen prediction recipes, learned parameter rules, portfolio allocation or archive retention.

- Select today's monitoring forecast using the city's current timezone, independently of a stored climate date. Refresh the climate cache on local date rollover using the existing page refresh.
- Bound a full-day maximum estimate by the observed maximum, preserving the canonical temperature's precision. Describe a cooling trend without claiming settlement.
- Resolve the Board's Live selection to its actual market date and read a single forecast for that city and day.
- Recognize the observation step in the hourly collector, check writer status as well as age, distinguish event activity from feed failures, and display current frozen-call learning reports.
- Sample the public evidence-health aggregate for pages on the existing refresh cadence; keep live verification and engine reads intact, expose sample age and reject overdue samples.
- Honor source retry instructions, defer long waits, skip final-weather requests until the city's day ends, and support bounded evidence-only manual recovery.
- Upgrade the web runtime and its affected dependencies, generating route types before a clean typecheck.

Validation requires both full regression suites, web types/routes/build, production repeatable-read comparisons of unaffected fields in both directions, exact checks of corrected fields, anonymous reads, preserved frozen receipts, and real collector/refresh runs after deployment. Deployment evidence belongs in the change's review record.

Capacity remains open: successful archival and reclaim jobs do not by themselves establish sufficient database headroom. Retention and stored history are unchanged. A clean monitoring interval is also required before declaring timeout and source-recovery reliability proven.
