### 8.2 P5.12 part 3b: the orders reach the shadow ledgers

This is the next build. The order path below was mapped from the code on 27 Sep by a read-only survey; read the code again before building:
- **Entry point.** The only automatic one is `public.publish_paper_plan(p_account, p_command, p_signal, p_legs, p_evidence, p_block_reason)` (`20260912083728_paper_approvals_exits_and_policies.sql`).
  - It **requires an ENTER `signals` row fired within the last 15 minutes**.
  - It inserts a plan that **expires 5 minutes** after it is written.
  - For an automatic desk it calls `arbdesk_private.queue_plan(plan, 'automatic')`. The latest `queue_plan` is in `20260924110000_fixed_risk_rails.sql`.
- **What `queue_plan` checks:**
  - the desk is not retired or suspended;
  - a shadow ledger only takes its own strategy;
  - `evidence.net_edge_per_share >= min_edge` (0 for shadow ledgers);
  - the halt and the 5% daily loss;
  - cash and caps;
  - per leg: `cash_ceiling`, the market open, price ≤ 0.97, not in the last 15 min, the city-day ≤ 3% of equity, and no existing holding or order on the same band and side.

  It then writes `paper_orders` BUY rows. **The orders inherit the plan's `expires_at`, 5 minutes.**
- **The legs.** They are built by `paper_plans.prepare` (form `{band_id, side, shares, limit_price, cash_ceiling}`, strings, one side per plan, equal shares per leg). `decision_engine` legs are `{band_id, side, order_type:'IOC', limit_price, usd, shares, depth_usd}`: convert them, and use one plan per side.
- **Filling.** `scripts/paper_worker.py cycle()` fills: `claim_paper_order` → `simulate` → `complete_paper_order`.
  - It runs **only** in `pipeline_intraday` (00/04/08/12/16/20Z) and in the dispatch-only `paper_fill.yml`.
  - **A tick-queued order would expire before any worker ran.**
  - So 3b must fill its IOC legs **inside the tick**, right after queueing: call `paper_worker.cycle` for those orders, or an equivalent single pass.
  - That has to fit the minute. Measure it.
- **Turning the strategies on.** Move them to `shadow` with `public.set_strategy_state(id, 'shadow', reason)`; `enabled` follows the state.
  - **Before that, make sure `signal_engine` skips engine ids.** It loads every enabled strategy (`signal_engine._enabled_strategies`).
- **Selling.** SELL and SWITCH (S10) need a consumer. `decide` never sells; S10's own rules say SELL/SWITCH, and the exit path exists (`submit_single_paper_exit`).

## 11. How to work here without repeating today's mistakes

- **Cut each branch from a freshly fetched `origin/main`**, after the previous PR merges. A branch cut from a stale base makes a dirty PR, and a dirty PR gets **no CI**. Check `mergeable_state`.
- **Merging through the GitHub MCP.** `expectedHeadSha` must be the **full 40-character SHA** (`git rev-parse HEAD`). Never guess the tail; a guess returns 409.
- **Apply a migration live before merging code that depends on it.**
  - Example: #222's tick code inserts `decisions` for ids that only the migration registers.
  - Verify with before-and-after counts.
  - Use `mcp__Supabase__apply_migration`, with exactly the committed SQL.
- **Watchers.**
  - `pgrep -f pattern` matches the watcher's own command line. Use `ps -eo pid,cmd | grep "[r]eplay"`, or wait on a PID or on a `done` file the job writes.
  - `pkill -f` can kill your own shell.
- **Timing measurements.** Don't run two heavy jobs at once (4 cores): the first shortcut timing was invalid for that reason.
- **Big `execute_sql` results** are saved to a tool-results file. Parse them with the regex helper: the JSON `result` field, then the `<untrusted-data-…>` block, then `json.loads`, as in `/tmp/claude-0/s10mw/parse.py` from this session; recreate it. Always check the row count against a `count(*)`.
- **The tick's sparse checkout.** Any repo file a tick script reads must be listed in `tick.yml`. `tests/test_tick.py::test_every_repo_file_the_tick_reads_is_checked_out` enforces it for the S10 model file. Extend it if the tick starts reading another file.
- **Raw `bands` / `markets` reads in `scripts/`** must be listed in `tests/test_one_bucket_convention.py` with what they read. Bounds come from `v_canonical_bands`.
- **Test-time budget.** The Python suite runs about 92–112 s. Engine-heavy tests should use few cases, with the shortcut on.
- **Every migration runs in PGlite** (`tests/database/paper-contracts.cjs`), in filename order. It must be idempotent and must not depend on production-only rows.
- **Replays and inputs are committed under `data/replay/`**, each with a README saying how it was built. A rerun should reproduce a report byte for byte; that was checked for P7.3 and the engine replay.
